# MEMORY//LAB 99 (preview)

This prototype turns the existing Vite memorAIzation-stAItion into a **complete provenance-safe practice loop** without replacing the main app. Navigate to `/lab.html` in the Vite development server, or build both entrypoints.

## Development

```bash
npm ci
npm run dev
# open http://localhost:5173/lab.html
node --test test/core.node.mjs
npm run build
```

Use the pink **ROLL//99** button to generate an unbiased random number 00–99, or enter a slot manually. Recall the answer, reveal it, choose a grade 0–5, and revisit due items. Data persists locally and can be exported as a full JSON backup or practice-attempt CSV.

## Roster reconciliation

The app loads the existing published 100-entry JSON as the default legacy source. The current Notion roster is intentionally *not* published here. Export it into a JSON array of `{Number,Initials,Name,Action,Item}` objects (or a `{"00":{"name":"..."}}` object map); upload it in the **Roster lab**. The workbench compares candidate people, actions, and objects side by side; selecting a binding changes only your local current choice. Historical candidates remain available.

`memory-lab-backup.json` contains sources, local selections and review events, and can be imported back into the lab. If you plan to import sensitive source material, keep the exported backup private.

## Three.js adapter

The optional **3D Preview** button dynamically fetches a pinned Three.js module from CDN when the browser has network access; the main 2D app never depends on that fetch. It builds a ten-quadrilateral-face d10, labels each face 0–9, and animates the authoritative digits generated by RollKit. This is **kinematic visualization**, not unbiased physical simulation. A production native build should bundle Three locally and subject face orientation, offline, and GPU performance to tests. iOS/watchOS should instead implement native presentation adapters to the same result schema.

## Boundary and safety

All app records stay local. No claims of auto-promotion to uINVERSE canon, no third-party AI calls, no embedded production credentials. The old legacy Rails server and tracked key are intentionally untouched.
